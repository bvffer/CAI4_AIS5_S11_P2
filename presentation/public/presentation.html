Architecture

Medallion Architecture

A three-tier data lakehouse pattern — raw data flows through Bronze, Silver, and Gold layers, each with a distinct purpose and level of quality.

Layer 1
Bronze
data/raw/
Untouched source CSVs. Six files from three CRM systems. Never modified — the original source of truth.
Layer 2
Silver
Python ETL
Cleaning, validation, and normalization. Casing standardization, typo correction, date parsing, FK integrity checks.
Layer 3
Gold
data/clean/ + PostgreSQL
Analysis-ready tables. Five gold tables plus an etl_batch audit log. The single source of truth for reporting.
Traceable

Every run is logged in the etl_batch table with timestamps, status, and notes.

Idempotent

Safe re-runs — staging tables are truncated before each load, so duplicate runs produce identical results.

Safe

Bad data is quarantined, never silently loaded into production. The row count invariant proves zero data loss.

etl/extract.py

Reads six CSV files from data/raw/ into pandas DataFrames, validating that required column headers exist before loading.

  • Reads contacts, customers, products, sales_orders, order_lines, and etl_batch CSVs from data/raw/
  • Validates that each CSV contains the required column headers
  • Returns a dictionary of DataFrames keyed by entity name for downstream processing
  • Logs the row count of each extracted file for traceability
etl/transform.py

Cleans and normalizes each entity's data — standardizing values, correcting formats, and parsing types so every record is consistent before validation.

  • Trims leading/trailing whitespace and tabs from all string fields
  • Validates UUID format for primary key columns
  • Validates and lowercases email addresses
  • Canonicalises department, segment, status, and category via lookup tables
  • Title-cases country names for consistency
  • Parses dates using three ISO format attempts (YYYY-MM-DD, with and without time)
  • Parses numeric prices and quantities, removing currency symbols and commas
  • Uppercases currency codes (e.g., 'usd' → 'USD')
etl/validate.py

Runs six sequential cross-row and cross-table validation checks, routing each record to Clean, Quarantine, or Rejected based on the type and severity of failure.

  • PK uniqueness — duplicate primary keys are quarantined
  • Required fields — missing mandatory fields trigger quarantine
  • Email uniqueness — duplicates trigger cascade quarantine (child records also quarantined)
  • SKU uniqueness — duplicates trigger cascade quarantine affecting order_lines
  • Email format — invalid format (missing @ or domain) triggers quarantine
  • FK referential integrity — child FK not in parent's clean set triggers quarantine
  • Outputs three sets of CSVs: clean, quarantine, and rejected
etl/load.py

Loads clean data into PostgreSQL via a two-stage process: bulk COPY into staging tables, then stored procedures upsert from staging into gold tables.

  • Truncates all staging tables to ensure idempotent re-runs
  • Bulk COPY clean CSVs into staging tables using psycopg2
  • Executes stored procedures: INSERT new records, UPDATE existing records
  • DELETE-then-reinsert strategy for uniqueness conflicts
  • Records each load as an etl_batch entry with timestamps and status
etl/reconcile.py

Verifies that no data was lost or duplicated during the pipeline run, by checking row count invariants and writing a structured reconciliation report.

  • Verifies: len(clean) + len(quarantine) + len(rejected) == len(raw)
  • Verifies: PostgreSQL staging row count == gold row count
  • Writes pipeline_summary_<timestamp>.json with per-entity counts
  • Writes per-run logs to etl/logs/<timestamp>/
  • Appends metrics to metrics.log for longitudinal tracking

Data Quality

Three-Tier Quality Classification

Every record is classified into exactly one of three tiers after validation. The classification is deterministic and auditable.

Rejected
Missing a primary key or mandatory field, or corrupted beyond repair (e.g., an unparseable date like "19967--30"). Permanently excluded from the pipeline.
data/rejected/<entity>.csv
Action: Fix at the source system. Never loadable.
Quarantine
Has a valid, non-null primary key but fails a quality check — a medium/high severity DQ flag, an FK cascade quarantine, or is the losing side of a deduplication.
data/quarantine/<entity>.csv
Action: Manual review. May be re-ingested after fix.
Clean
Passed all NOT NULL, FK referential integrity, UNIQUE (no duplicate emails or SKUs), and CHECK constraints (non-negative prices, positive quantities).
data/clean/<entity>.csv
Action: Loaded into PostgreSQL gold tables.
